# Artifact Reuse Audit - Karaoke MFA Multi

Date: 2026-05-28

## Executive Summary

The current pipeline still allows mutable artifact reuse across stages. The most visible symptom is karaoke subtitle output changing between runs because `output.ass` and `output.mp4` are overwritten in place and Stage 07 trusts whichever `output.ass` exists at render time.

This is not just a visual style issue. It is a provenance issue:

- Stage 06 writes `output.ass`, but does not create a binding manifest that proves which `analysis.json`, preset, style library, renderer implementation, and command generated it.
- Stage 07 renders `output.mp4` from whatever `output.ass` is present, without verifying that it came from the latest Stage 06 run.
- Review/preview/export paths can copy or serve artifacts by filename, so stale-but-valid files can survive and look official.
- Long-running server/test processes can continue using earlier code or trigger flows whose assumptions no longer match the source tree.

The evolved standard should be: every derived artifact must carry provenance, every downstream stage must verify that provenance, and final/preview exports must be immutable snapshots or explicitly linked to a run id.

## Reuse Points That Violate The Evolved Standard

### 1. Pipeline Runner Reuses Mutable Final Filenames

Location: `scripts/pipeline_runner.py`

Current behavior:

- Always uses the same job directory.
- Always writes canonical names such as `analysis.json`, `output.ass`, and `output.mp4`.
- Does not allocate a run id.
- Does not clean or quarantine stale downstream artifacts before rerunning partial stages.

Risk:

- A rerun of Stage 07 can render an old or externally modified `output.ass`.
- A rerun of Stage 06 can leave an old `output.mp4` that still appears export-ready.
- `status.json` and `events.jsonl` append/update but do not establish a single coherent artifact graph.

Recommended standard:

- Introduce `run_id` for each pipeline execution.
- Write derived artifacts under `runs/{run_id}/...` or write canonical outputs only after all provenance checks pass.
- Before any stage rerun, invalidate downstream artifacts and record that invalidation.

### 2. Stage 06 Writes ASS Without A Provenance Manifest

Location: `scripts/s06_generate_ass.py`

Current behavior:

- Reads `analysis.json`.
- Chooses a preset.
- Writes `output.ass`.
- Records artifact size, but not enough identity.

Missing:

- `analysis.json` SHA256.
- selected preset id/version.
- style library SHA256 or version.
- Stage 06 script/version hash.
- renderer mode, for example `single_layer_kf`.
- dialogue count expected from `analysis.lines`.
- whether any `Base` styles/dialogues were emitted.

Risk:

- A valid `output.ass` can be stale, dual-layer, wrong preset, wrong style library, or generated by old code.
- Events can claim one artifact while the file on disk later becomes another artifact.

Recommended standard:

- Write `output.ass.manifest.json` atomically with:
  - `run_id`
  - `stage: "stage06"`
  - hashes of `analysis.json`, `s06_generate_ass.py`, and `scripts/karaoke_styles/library.py`
  - preset id/version/effect profile
  - output hash/size/dialogue count
  - renderer invariant: `dialogue_count == len(analysis.lines)` for single-layer mode
- Stage 06 should fail if it emits `Base` styles unless explicitly in a legacy dual-layer mode.

### 3. Stage 07 Trusts Any `output.ass`

Location: `scripts/s07_output.py`

Current behavior:

- Checks that `output.ass` exists, is non-empty, and contains `[Script Info]`.
- Passes it to ffmpeg.
- Overwrites `output.mp4`.

Missing:

- No manifest requirement.
- No hash match against the latest Stage 06 output.
- No check that `output.ass` is newer than or derived from the current `analysis.json`.
- No check that `dialogue_count` matches the current analysis contract.
- No record of the ASS SHA embedded into the MP4 artifact event.

Risk:

- This is the main point where mixed results become user-visible.
- It can burn a stale or externally rewritten subtitle file into a fresh MP4.

Recommended standard:

- Stage 07 should refuse to render unless `output.ass.manifest.json` exists and validates.
- Stage 07 should write `output.mp4.manifest.json` that includes the exact ASS hash and input audio hashes used.
- The `stage07.output_written` event should include the ASS hash, output hash, and upstream manifest id.

### 4. Validation Checks Shape, Not Cross-Artifact Provenance

Location: `scripts/s08_validate.py`

Current behavior:

- Validates contracts and basic subtitle health.
- Detects overlap/timing issues.
- Checks source distribution for Stage 04.

Missing:

- No check that `output.ass` was generated from the current `analysis.json`.
- No check that `output.mp4` was rendered from the current `output.ass`.
- No check for stale output mtimes or mismatched event/file sizes.
- No check that `stage06.ass_written.size_bytes` equals current `output.ass` size.

Risk:

- Validation may pass or partially pass while the final render is a mixed artifact.

Recommended standard:

- Add a provenance validation section:
  - `analysis_hash == ass_manifest.input.analysis_sha256`
  - `ass_hash == mp4_manifest.input.ass_sha256`
  - current files match their recorded hashes
  - no legacy dual-layer `Base` styles unless declared
  - final artifacts are newer than all declared inputs or have a matching immutable run id

### 5. Review Wizard Copies And Serves Existing Artifacts

Location: `server.py`

Current behavior:

- Full preview render copies `output.mp4` to `preview_full.mp4`.
- Approval captures artifact fingerprints.
- Final artifact routes block after review if approved fingerprints change.

What is good:

- Review approval already records hashes.
- Final routes already have some fingerprint-based blocking.

Remaining gap:

- Preview creation trusts the existing `output.mp4`.
- The review project can be created around stale artifacts.
- `technical_export_ready` is existence-based: `output.mp4` and `output.ass`.
- Final route protection happens around review approval, not around pipeline provenance.

Recommended standard:

- Preview creation should require a valid `output.mp4.manifest.json`.
- Review project creation should record the current run id and artifact graph.
- `technical_export_ready` should mean provenance-valid, not just file-exists.

### 6. Server/Process Lifetime Can Keep Old Behavior Alive

Observed process:

- `python.exe server.py` was still running from 2026-05-27 15:35.
- Current source files were edited after that.

Risk:

- UI options, defaults, route behavior, and in-memory imports can diverge from source on disk.
- A user can unknowingly trigger a job through an old process while inspecting newer files.

Recommended standard:

- Add startup logging with source hashes for `server.py`, `pipeline_runner.py`, `s06_generate_ass.py`, and `karaoke_styles/library.py`.
- Add a `/healthz` or dashboard display showing process start time and source hash.
- Restart server after style/rendering pipeline changes.

### 7. Test Pipeline Bypasses The Style Selection Contract

Location: `scripts/test_pipeline.py`

Current behavior:

- Calls Stage 06 without passing a preset.
- This uses Stage 06 default rather than the job/meta/UI style selection.

Risk:

- Integration tests can validate a different style path than the product path.
- Default changes can hide mismatches.

Recommended standard:

- Test pipeline should read `meta.json.preset` or `pipeline.toml` and pass `--preset` explicitly.
- It should assert Stage 06/07 manifest consistency.

### 8. Artifact Observability Records Size, But Not Content Identity

Location: `scripts/common/observability.py`

Current behavior:

- `record_artifact` records file presence and size.

Missing:

- SHA256 hash.
- writer stage/run id.
- dependency hashes.

Risk:

- Event logs can prove that a file of a certain size existed, but not that the current file is the same file.

Recommended standard:

- Extend artifact details with SHA256 for small/medium artifacts by default.
- For large media, compute SHA256 at the writer stage and store it in the manifest/event.

## "About To Snap" Golden Example

The last "About to snap" in Struggle is the line around:

- line text: `About to snap`
- line start/end: `274.48s -> 282.02s`
- words:
  - `About`: `274.48s -> 275.22s`
  - `to`: `275.26s -> 275.31s`
  - `snap`: `275.42s -> 282.02s`

In both `struggle-karaoke-single-style` and `real-struggle-20260522`, the aligned words are marked:

- `source: "ctc_forced"`
- no LLM timing method
- no Whisper timing method

In older `jobs/struggle_test`, the same phrase is marked:

- `source: "ctc_forced+hubertfa"`
- `snap`: `275.37s -> 281.59s`

The current visually best behavior comes from two layers working together:

1. Forced lyric alignment preserves the long sung word duration instead of compressing the word.
   - Stage 03b uses known lyrics and CTC forced alignment.
   - Stage 04 can preserve provider timing as `ctc_forced` when HubertFA is skipped/unavailable, or enrich it as `ctc_forced+hubertfa` when valid phoneme intervals exist.

2. Highlight velocity splits sustained words at render time.
   - `build_word_highlight_segments()` detects long words above `1.2s`.
   - For `snap` it derives:
     - `sn`: `275.42s -> 275.60s`, role `consonant_attack`
     - `a`: `275.60s -> 281.84s`, role `sustained_vowel`
     - `p`: `281.84s -> 282.02s`, role `consonant_release`
   - Stage 06 renders this as:
     - `About` normal highlight
     - `to` minimum visible highlight
     - `sn` short attack
     - `a` long sustained sweep
     - `p` short release

Generated karaoke text for the golden line:

```ass
{\be1\kf74}About {\k4} {\be1\kf8}to {\k8} {\be1\kf18}sn{\be1\kf624}a{\be1\kf18}p
```

This should be the standard for sung sustained words:

- preserve the real phrase/word duration from forced alignment;
- do not resegment the phrase with an LLM;
- do not collapse long word endings;
- split long words into attack, sustained vowel, and release during ASS generation;
- keep one visible dialogue layer.

## Proposed Implementation Standard

### Required Invariants

- Stage 06 single-layer mode: `ASS dialogue_count == len(analysis.lines)`.
- No `Base` styles/dialogues unless `renderer_mode == "dual_layer_legacy"` is explicitly requested.
- Stage 07 cannot run without a valid Stage 06 manifest.
- `output.mp4` cannot be considered current unless its manifest references the current `output.ass` hash.
- UI export readiness cannot be file-existence based.
- Long sustained words use the highlight velocity splitter by default.

### Recommended Artifact Graph

```text
transcript.json
  -> aligned.json + aligned.manifest.json
  -> analysis.json + analysis.manifest.json
  -> output.ass + output.ass.manifest.json
  -> output.mp4 + output.mp4.manifest.json
  -> preview_full.mp4 + preview_full.manifest.json
```

Each manifest should include:

- `run_id`
- `stage`
- `created_at`
- `command`
- input artifact hashes
- output artifact hash
- style preset id/version where relevant
- renderer mode where relevant
- source script hashes or application version

### Immediate Fix Priority

1. Add `output.ass.manifest.json` in Stage 06.
2. Make Stage 07 require and validate the ASS manifest.
3. Add `output.mp4.manifest.json` in Stage 07.
4. Extend Stage 08 to validate the artifact graph.
5. Make review/export readiness depend on provenance validity.
6. Restart the long-running server after these changes.
7. Regenerate Struggle examples from a clean run id.

## Open Questions

- Should canonical `output.ass`/`output.mp4` remain as convenience symlinks/copies to the latest valid run, or should the UI navigate directly to `runs/{run_id}` artifacts?
- Should legacy dual-layer ASS be supported behind an explicit preset/render mode, or removed entirely?
- Should `ctc_forced+hubertfa` be preferred only when phoneme intervals pass quality gates, falling back to pure `ctc_forced` for long sustained words?
